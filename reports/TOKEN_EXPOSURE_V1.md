# 탐색 v1 추가 진단: 평가 입력의 미노출 토큰

기존 데이터와 토크나이저를 읽기만 하는 CPU 진단이다. 모델 재학습·GPU 사용·데이터 수정은 없다.
재현 도구: `scripts/audit_token_exposure.py`. 수치: `reports/token-exposure-v1.json`.

| 언어 | dev A 미노출 토큰 비율 | dev B 미노출 토큰 비율 | 평서문으로 재표현한 dev A/B |
|---|---:|---:|---:|
| 영어 | 71.41% | 71.61% | 0% |
| 독일어 | 76.83% | 75.43% | 0% |
| 한국어 | 68.07% | 70.71% | 0% |

비율은 SEP/EOS를 포함한 전체 토큰 **출현 횟수** 중, 세 언어 학습 입력 전체에서 한 번도
등장하지 않은 토큰 ID의 출현 횟수다. UNK 비율이나 어휘 종류 비율이 아니다.
기존 whole-string BPE는 학습 평서문을 긴 덩어리로 병합한다. 미학습 외곽 문장 틀에서는
분해가 달라지며 학습에 노출되지 않은 작은 토큰도 대량으로 등장한다. 따라서 현재 평가는
문장 틀·길이·토큰 표현의 변화를 동시에 포함한다. 이 사실만으로 실패의 유일한 원인을
확정하지 않으며, EN/DE의 낮은 학습 정확도는 별도 설명이 필요하다.

## 서버에서 가장 먼저 할 일: 새 학습 없이 기존 체크포인트 평가

1. 기존 탐색 v1 결과·체크포인트·데이터를 보존한다. 5개 런의 `primary.pt`를 사용하고
   파라미터를 업데이트하지 않는다. CPU에서 만들어지는 입력의 scene/ID/label이 바뀌지
   않는지 확인한다.
2. `scripts/audit_token_exposure.py`의 `assertion_view(row)`를 사용해 dev A/B의 같은
   미학습 의미 조합을 평서문으로 렌더링한다. 이 함수는 원본 파일을 수정하지 않는다.
3. 단일언어 체크포인트는 해당 언어, 순차·혼합 체크포인트는 세 언어를 평가한다.
   원본 문장과 평서문 진단 문장을 각각 같은 체크포인트에서 비교한다.
   네 과제별 정확도·정답 수·문항 수·토큰 길이·학습 미노출 토큰 비율을 보고한다.
   원본의 정규 숙달·종료 시점이나 기존 독립 시험 결과를 다시 쓰지 않는다.
4. 탐색 예비비에서 평가 전체에 최대 0.25 GPU시간을 새로 예약한다. 기존 활성 작업을
   확인하고 GPU 하나에서 순차 평가한다. 실패·중단을 포함한 실제 시간을 기록한다.
5. 결과는 `reports/frame-diagnostic-v1.json`에 별도 저장한다. 평서문 진단은 외곽 틀 보류
   요건을 완화했으므로 기존 확증 평가로 간주하지 않는다. 추가 사용자 검수 자료를 요청하지 않는다.
6. 새 학습은 이 진단 뒤에 결정한다. 특히 KO가 평서문에서도 우연 수준이면 학습 문항
   암기가 새 의미 조합으로 전이되지 않은 것이고, 평서문에서만 높으면 입력 표현/외곽 틀
   변화가 주요 조사 대상이다. EN/DE는 기존 학습 정확도부터 낮아 장기 기억·최적화 문제도
   남는다. 임계값을 낮추거나 언어별로 유리한 설정을 따로 선택하지 않는다.

후속 데이터에서는 원래 의미·번역·오답의 분할을 유지하며, 같은 표현 분포의 일반화와
미학습 외곽 틀 전이를 별도 평가로 분리한다. 그때 입력 표현을 바꾸면 모든 언어를 같은
새 조건에서 비교해야 한다. KO 표현 수정과 토크나이저 변경을 기존 체크포인트 진단에 섞지 않는다.
