# 서버 Codex에 붙여넣을 프롬프트

아래 구분선 이후를 복사한다. ZIP을 서버에 옮겨 압축을 푼 뒤 `fly-language-study` 폴더에서 Codex를 시작한다.

---

현재 폴더의 `fly-language-study` 연구 구현을 이어서 실행해줘. 목적은 동일한 학습 가능한 실제 5,000뉴런 초파리 커넥톰 모델에서 영어·독일어·한국어 네 의미 과제의 도달 비용과 여섯 언어 순서를 비교하는 연구계획 v4다. 이 서버에는 RTX 3080 Ti 두 장을 사용할 계획이다. 새 구현을 처음부터 만들지 말고 전달된 코드를 검사하고 이어받아라.

먼저 `README.md`, `docs/PROTOCOL_V4.md`, `docs/SOURCE_AUDIT.md`, `reports/implementation-status.json`, `reports/power-summary.json`을 읽어라. 다음 지시를 작업 순서와 중단 기준으로 사용해라.

1. 파일을 갱신하기 전에 `python scripts/verify_handoff.py`로 전달 무결성을 확인해라. 서버 OS·GPU 두 장·드라이버·nvcc·Python을 확인하고 프로젝트 전용 가상환경을 구성해라. CUDA PyTorch는 실제 서버와 호환되는 버전을 공식 문서로 확인해서 설치해라. 로컬 CPU 환경의 torch를 그대로 복사하지 마라. `CK_CUDA_ARCHS=86`으로 `connectome-kernels` 커밋 `c6be4cfea8ca2210098ef52344b88e85c683fd5c`를 설치하고 설치 버전과 빌드 명령을 기록해라.

2. 전달된 `artifacts/graphs/real.npz`, `data/draft-v4.3/`, `artifacts/tokenizer-v4.3.json`, `artifacts/power/final-grid.jsonl`을 확인해라. 실제 배선은 5,000뉴런·524,324개 엣지이고 구조 해시는 `04da699665813da82680186a25240c8b3106f8144cb46f51e3eb7ae2524d8d5e`다. 학습된 HF 가중치를 모델에 넣지 마라. 문항·토크나이저·코드 해시는 상태 보고서와 비교해라. 이전 초안을 섞지 마라.

3. `python -m pytest -q`, 데이터 감사, CPU smoke를 실행해라. GPU 작업 전 `configs/startup-reservations.json`으로 `runs/gpu-ledger.json`에 예산을 예약해라. 기존 장부가 있으면 중복 예약하지 말고 상태부터 읽어라. 총 예산은 672 GPU시간이다. G0를 두 sm_86 GPU에서 수행해 실제 분류 경로의 출력·모든 기울기·마이크로스텝 2/4·패딩·누적·평가 상태 보존을 검증해라. 스킵, CPU 참조 실행, 커널 fallback을 통과로 바꾸지 마라.

4. G0 통과 후 두 GPU의 처리량·VRAM을 물리 배치 32/64/128/256에서 측정하고 유효 배치 256을 유지해라. G1은 128문항, 2,000업데이트 이내 전체 98%·유형별 95% 기준이다. 코드가 필요하면 수정하고 해당 검증을 다시 수행하되, 근거 없이 임계값을 완화하지 마라. 각 작업의 학습·평가·저장·실제 GPU시간을 기록해라.

5. 현재 검수 방식은 사용자가 승인한 Claude 단독 검수다. `docs/AI_REVIEW_GUIDE.md`에 따라 실제 분리된 여섯 세션의 모델·요청문·입력·원응답·대화 기록을 수집하고 `certify-ai-review`로 인증해라. 새 설정은 `configs/protocol-v4-ai.json`이다. 사람 검수로 등록하지 마라. KO fluent=no의 사유 누락은 해당 Claude 세션에서 보완받고 원응답을 보존해라. 코드가 사유나 판정을 대신 만들지 마라. 코드 해시가 바뀌었으므로 기존 G0/G1 해시를 수정하지 말고 새 예약·새 보고서로 재검증해라. 인증과 현재 G0가 없으면 파일럿을 시작하지 마라.

6. 검수 통과 후 별도 파일럿 시드로 G2와 전체 A/B 패널을 기록하는 언어별 평가 해상도 보정, G3 혼합, 여섯 실제 순서 파일럿을 진행해라. 처음 두 시드로 시작하되 두 개가 충분하다고 가정하지 마라. 파일럿 비용과 보정용 여섯 런 비용을 각각 G2/G3/order_pilot 장부에 넣어라. 평가 간격 후보 5,120/10,240/20,480을 검토하고 선택한 간격으로 실제 순차 학습을 실행해라. 로그 다운샘플링으로 다른 순서 정책을 재현했다고 주장하지 마라.

7. 완성된 사전 시뮬레이션은 각 설계 5,000회 반복의 가정별 지도다. 실제 모델 검정력이 아니다. 파일럿의 분산·미도달률·처리량·전체 평가 비용과 불확실성을 갱신해서 `pilot-report`, `resolution-report`, `cost-report`, `assess-design`을 생성해라. 관측 효과 크기로 표본 수를 선택하지 마라. 필요한 시드 블록을 추가할 예산이 없거나 시뮬레이션 범위 밖이면 본실험을 시작하지 말고 필요한 추가 시드·GPU시간을 계산해라.

8. 승인 가능할 때만 N=10/15/20과 공통 평가 간격을 고정하고 `freeze`해라. N 최대화→평가 간격 축소→보조 연구 순서로 선택한다. 각 시드의 단일 언어 3개·여섯 순서·혼합 1개, 총 10런을 두 GPU `campaign`으로 실행한다. 순서 조건을 삭제하거나 유리한 시드만 고르지 마라. 주 런은 동시 숙달 즉시 종료한다. 독립 시험은 종료 체크포인트에 한 번만 적용한다.

9. 고정 복습·셔플·토크나이저 연구는 별도 예산의 완전 대응 묶음이 들어갈 때만 진행해라. 예산이 부족하면 고정 복습→셔플→토크나이저 순서로 줄여 주 연구에 재배정한다. 고정 복습은 시드 1·2의 여섯 순서 전체만 선택한다. 모든 본실험을 추가로 30만 문항씩 학습하지 마라.

10. 기술 오류와 예산 중단을 행정적 미도달로 처리하지 마라. 재개는 새 예약 ID로 기존 체크포인트·옵티마이저·RNG·샘플러 상태를 복원한다. 강제 종료 비용은 서버 기록으로 회계에 복구한다. 연구 결과는 시드를 독립 단위로 한 두 계획 대비, 양측 대응 t 검정·Holm·RMST·신뢰구간·시드 블록 부트스트랩으로 분석한다. 학습·망각 곡선과 실제 GPU시간, 실패·미완료 사유를 함께 제공해라.

진행 중에는 완료한 검증, 아직 측정하지 않은 항목, 다음 중단 조건을 짧게 보고해라. 사용자가 이미 승인한 구현·검증 범위의 작업은 불필요하게 재확인하지 말고 수행해라. 실제 Claude 증거나 다른 필수 입력이 없으면 해당 게이트를 넘지 마라. 어떤 단계가 막히면 독립적으로 가능한 작업까지 마친 뒤 정확히 필요한 파일·정보를 알려줘. CUDA 검증 전의 코드나 CPU smoke를 실제 GPU 실험 성공으로 표현하지 마라. 커밋 작성자는 사용자만 유지하고 AI 공동 작성자 표기를 넣지 마라.
