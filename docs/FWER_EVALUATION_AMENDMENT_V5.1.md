# FWER 승인 평가의 Monte Carlo 정밀도 개정 — 설계 버전 v5.1-extended-N-2 (기록 2026-09-17T15:51:18Z)

**이 개정의 성격.** 확장 판정(`reports/design-extended-v5.1.json`, 5,000회)이 FWER 기준에서 차단된 것과, 판정에 쓰지 않는 50,000회 진단
(`reports/fwer-highrep-diagnostic-v5.1.json`)의 결과를 **이미 확인한 뒤**, 본실험을 하나도 실행하기 전에 운영자 지시로 채택한 절차 개정이다.
처음부터 사전 등록돼 있던 규칙이 아니며 그렇게 표현하지 않는다. 기존 차단 보고서·진단 보고서·사전 등록 문서(`docs/EXTENDED_DESIGN_V5.1.md`)는
수정하지 않고 보존한다. 기계 판독용 기록은 `reports/fwer-evaluation-amendment-v5.1.json`(알고 있던 수치와 해시 포함).

## 사유

5,000회 반복에서는 참 FWER이 정확히 0.05여도 Wilson 95% 상한이 약 0.056이고, 판정은 N마다 영가설 34행의 상한 **최댓값**을 본다. 이 조합에서는
몬테카를로 잡음만으로 0.06을 넘을 확률이 약 0.99다(`reports/MAIN_STUDY_PLAN_V5.md` 7.5절). 기준이 1종 오류가 아니라 시뮬레이션 잡음을 재고 있었으므로,
상한 0.06은 그대로 두고 반복 수를 늘려(Wilson 반폭 약 0.002) 기준이 오류율 자체를 검사하게 한다.

## 유지하는 것

FWER 승인 상한 0.06(판정 범위의 모든 영가설 행 Wilson 95% 상한의 최댓값); 실제 검정(두 계획 대비, 양측 대응 t, Holm 0.05)과 보수적 검정력 정의(원 p < .025,
효과 20%); 검정력 기준 0.80(5,000회 확장 격자의 검정력 행을 그대로 재사용); 판정 범위(잠재 상관 0, 두 분포, 검열 격자 상한까지, 파일럿 산포 상한의 격자 경계까지);
평가 간격 5,120, 숙달 임계 0.8, 상한 200,000/900,000; N 선택·예산 규칙(`choose_design`: 1.25배 GPU·달력 시간 안에서 통과 후보 중 최대 N, 보조 배정 해제 순서).

## 바꾸는 것

- FWER 평가 반복 수를 영가설 시나리오당 **50,000회로 고정**한다.
- 영가설 행은 공식 CPU 실행 한 번으로 만든다: `scripts/fwer_official_verification.py` — 확장 격자의 잠재 상관 0 영가설 시나리오 전부
  (원 CV 9 × 검열 3 × 분포 2 × target 2 = 108개, N 20–100), `flystudy.statistics.simulate` 그대로, 시드 29401 + 시나리오 번호
  (격자 9401+, 진단 19401+, 원 격자 8401+와 겹치지 않음). 출력 `artifacts/power/fwer-official-v5.1.jsonl`.
- 코드·시나리오·시드·반복 수는 실행 전에 커밋으로 고정한다. 스크립트는 출력이나 시작 표식이 있으면 다시 실행되지 않는다. 통과할 때까지 시드나 반복 수를 바꿔
  재시도하지 않는다.

## 시나리오 대응 검증 (`reports/fwer-scenario-correspondence-v5.1.json`)

- 판정 범위의 영가설 행은 모든 N에서 같은 34행 = 생성 분포 17개(분포·검열·CV) × target 2개다. 진단은 target 0만 돌려 17행이었다.
- 영가설에서는 효과 배율이 1.0이라 `raw[:, :, treatment] *= factor`가 자료를 바꾸지 않는다. target 표지만 다른 두 시나리오를 같은 시드로 돌리면 모든 산출값이
  동일함을 확인했다(대응 보고서와 `tests/test_fwer_official.py`). 즉 두 target 행은 같은 분포의 독립 몬테카를로 반복이다.
- 영가설 행의 비율은 `rejects.any(1)`, 곧 두 대비 중 **하나라도** Holm 보정 후 잘못 기각할 확률이다(같은 테스트가 확인).
- 공식 판정에서는 **중복 제거를 쓰지 않는다.** 두 target을 모두 시뮬레이션해 34행 각각에 공식 대응 행을 두고, 그 전부의 Wilson 상한 최댓값을 쓴다.
  불리한 시나리오를 제외하지 않으며, 대응 행이 하나라도 없으면 판정 스크립트가 거부한다. 판정 범위 밖 74개 시나리오도 함께 돌려 보고만 한다.

## 재판정

`scripts/extended_design_decision.py --fwer-report …`(설계 버전 v5.1-extended-N-2)가 검정력은 기존 격자에서, 거짓 양성 상한은 공식 보고서에서 읽어
기존 규칙으로 판정한다. 통과하면 선택된 N으로 `configs/protocol-v5.1-main-N<N>.json`(`main_seeds`만 30001부터 N개) → `freeze` → 예약 → 본실험.
실패하면 차단 행을 구체적으로 보고하고 멈춘다. 추가 검수나 GPU 파일럿은 시작하지 않는다. 운영자가 예상한 선택은 N=80(800런)이지만 강제하지 않는다.
